مَدار — تجهيز النشر على Vercel وSupabase

الحزمة مجهزة لتُرفع إلى GitHub ثم تُنشر على Vercel. Supabase يحفظ الحسابات والعملاء والأنشطة والعروض والمشاريع في PostgreSQL.

قبل النشر
1. أنشئ مشروعًا في Supabase واختر Frankfurt (Central EU) إن كانت متاحة. تم ضبط API في Vercel على Frankfurt (`fra1`) لتقريب الاتصال من قاعدة البيانات.
2. افتح SQL Editor في Supabase، ثم نفّذ الملف supabase/schema.sql كاملًا.
3. من زر Connect في Supabase انسخ رابط Shared Pooler بنمط Transaction (المنفذ 6543) كاملًا. استخدم الرابط كما هو، بما فيه اسم المستخدم الذي يحدده Supabase، ولا تحاول تركيب اسم المضيف يدويًا.
4. ارفع ملفات هذا المستودع إلى GitHub. التطبيق موجود في جذر المستودع، لذلك اترك Root Directory في Vercel فارغًا.
5. اربط المستودع في Vercel، واختر Framework Preset = Other. مجلد الواجهة هو public ومحدد في vercel.json. اترك Build Command فارغًا.
6. في إعدادات Vercel > Environment Variables أضف:
   DATABASE_URL = رابط اتصال PostgreSQL المنسوخ من Supabase.
   SESSION_SECRET = سر عشوائي طويل لا يقل عن ٣٢ حرفًا. لتوليد قيمة على جهازك شغّل: node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))" ثم انسخ الناتج إلى Vercel.
   أضف المتغيرين لبيئة Production، ثم أعد النشر بعد حفظهما.
7. افتح رابط الموقع. أول زيارة تنشئ حساب المدير. بعد الدخول أضف أفراد السيلز من صفحة «فريق السيلز».

مهم
- لا ترفع ملف .env أو كلمة مرور قاعدة البيانات إلى GitHub. استخدم إعدادات Vercel السرية فقط.
- لا تضع DATABASE_URL في ملفات JavaScript أو أي متغير يبدأ بـ NEXT_PUBLIC.
- عند أول إعداد للمدير، النظام يحمّل سجلات واتساب المنشورة فقط. الملف الحالي يحتوي ٣٣ سجلًا من أصل ٢٣٥، لأن بقية السجلات ليس لها رابط واتساب منشور في المصدر.
- وجود رابط واتساب منشور لا يثبت أن الحساب ما زال نشطًا أو يقبل الرسائل. زر واتساب يفتح الرابط، وتراجع الرسالة وترسلها بنفسك.
- النسخة المحلية القديمة الموجودة في data/madar-db.json لا تنتقل تلقائيًا إلى Supabase. صدّر بياناتك المهمة قبل الانتقال، ثم استورد ملف CSV بعد النشر.
- حذف العميل يحذفه من قاعدة النظام. إيقاف حساب السيلز يمنع دخوله ويعيد عملاءه إلى قائمة غير المعيّنين مع الاحتفاظ بسجلات النشاط.
- احتفظ بنسخة احتياطية من قاعدة Supabase بانتظام، واستخدم تصدير CSV من النظام لنسخة العملاء.

للتشغيل المحلي التجريبي فقط
شغّل run-madar.bat واترك نافذته مفتوحة، ثم افتح http://127.0.0.1:3210. بيانات التشغيل المحلي محفوظة في outputs/data؛ هذه ليست قاعدة البيانات السحابية.
